# AcreIQ checkpoint recording

## Repeatable capture procedure
Start the local backend and web app. Open the labeled sample, confirm its assumptions and run
Compare lighting scenarios. Switch Current/Proposed, show the real candidate plot, then export JSON.
Save the JSON beside the video with the commit SHA. This proves which assumptions generated the result.
For a photo run, keep the actual photograph and observations private unless you have permission to publish them.

## 75–90 second script
**0–15 seconds, the problem:** "AcreIQ helps growers test how to use existing infrastructure before
buying more. We start with the growing environment and resources already there."

**15–30 seconds, the entry point:** "You can scan a photo, enter your setup, or explore a sample.
Vision suggests visible assets. Measurements and operating constraints are reviewed by the user."

**30–60 seconds, evidence:** "This milestone evaluates lighting scenarios. Here are the current
load, crop-light constraint and operating schedule. These dots are actual configurations evaluated
by Python. Gray settings fail the constraints; green settings pass. This is the selected setting
and its calculated energy difference. The visual twin is a schematic, not a measured reconstruction."

**60–75 seconds, honesty:** "These are scenario estimates, not measured savings or a crop-yield
prediction. Water and avoided purchases stay unestimated until their models are validated."

**75–90 seconds, direction:** "Next, the same resource-first workflow will evaluate feasible physical
layouts with measured equipment footprints and clearances. Optimize first. Purchase second."

## Before recording
- Backend starts; sample runs; repository revision recorded.
- No credentials, personal email addresses or console secrets on screen.
- Do not say a model call was live when using the sample.
- Do not reuse the earlier invented 4,862-count/15%/20% cards as verified outcomes.
- Show limitations without burying the main demo in implementation details.

## Each submission
Record what changed, what works, the current limitation, the next milestone, the repo/commit,
and the exported input/result file. Use the organizer's actual deadline and format.
A 60–90 second duration is an internal production target, not a confirmed event rule.
