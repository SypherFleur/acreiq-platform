# AcreIQ checkpoint recording

## Repeatable capture procedure

Start the local backend and web app. Open the labeled sample, confirm its
assumptions and run Run simulation. Switch Current state/Proposed state, open
Scenarios, show the real candidate plot, then export JSON. Save the JSON beside
the video with the commit SHA. This proves which assumptions generated the
result. For a photo run, keep the actual photograph and observations private
unless you have permission to publish them.

## 75-90 second script

**0-15 seconds, the problem:** "AcreIQ helps existing controlled-environment
operators test how to use current infrastructure before expanding. Lettuce is
our first benchmark crop, and we start with the growing environment and
resources already there."

**15-30 seconds, the entry point:** "You can scan a photo, enter your setup, or
explore a sample. Vision suggests visible assets. Measurements and operating
constraints are reviewed by the user."

**30-60 seconds, evidence:** "This milestone evaluates lighting scenarios using
entered loads, a flat tariff, crop-light constraints and reviewed operating
schedules. These dots are actual configurations evaluated by Python. Gray
settings fail the constraints; green settings pass. This is the selected setting
and its calculated energy difference. The visual twin is a schematic, not a
measured reconstruction."

**60-75 seconds, honesty:** "These are scenario estimates, not measured savings,
a complete utility-bill model or a crop-yield prediction. Conditional output
benchmarks are reviewed assumptions, and the synthetic sample stays clearly
labeled."

**75-90 seconds, direction:** "Next, operator validation uses bills, interval
data, schedules and harvest records with separate calibration and held-out
periods. The broader resource-planning direction remains: optimize first,
purchase second."

## Before recording

- Backend starts; sample runs; repository revision recorded.
- No credentials, personal email addresses or console secrets on screen.
- Do not say a model call was live when using the sample.
- Do not reuse the earlier invented 4,862-count/15%/20% cards as verified outcomes.
- Show limitations without burying the main demo in implementation details.

## Each submission

Record what changed, what works, the current limitation, the next milestone, the
repo/commit, and the exported input/result file. Use the organizer's actual
deadline and format. A 60-90 second duration is an internal production target,
not a confirmed event rule.
